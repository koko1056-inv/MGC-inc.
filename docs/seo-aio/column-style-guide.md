# コラムの書き方とサムネイルの標準（column-style-guide）

このファイルは、MGCのコラム（`/column/*`）を書くとき・直すときの標準。
基準は、代表の評価が高かったコラム「[法人向けAI研修の選び方チェックリスト](https://mgc-global01.com/column/ai-training-selection-checklist)」（`content/columns/ai-training-selection-checklist.json`）。
新しいコラムは必ずこの標準に従う。日次の自動投稿（`scripts/column/generate-column.mjs`）も、この記事を見本にしている。

---

## 1. 記事の型

### 1-1. 全体の流れ（この順番で固定）
| 順 | 要素 | 中身 |
|:--|:--|:--|
| 1 | タイトル | 「テーマ — 読者が得るもの」。全角ダッシュ（—）で2つに分ける。32〜40字前後 |
| 2 | リード（`lead`） | 2〜3文。①よくある見方・誤解 → ②本当に大事な点 → ③この記事で何を整理するか |
| 3 | 要点（`summary`） | 3点。各1文で結論を言い切る。ここだけ読めば要旨が分かる |
| 4 | 前提の節（h2） | 「比べる前に決めること」「まず決めること：〜」など、判断の前に決めておくことを先に置く |
| 5 | 観点の節（h2 を4〜5本） | 1節＝1観点。「チェックリスト1：〜」のように番号＋観点の見出し。中身は「確認項目の箇条書き → なぜ大事かの段落」 |
| 6 | MGCの場合（h2） | 「MGCの〜の場合」。公開済みの事実だけで、MGCではどうしているかを短く書く |
| 7 | サイト内リンク（`links`） | 関連ページへのリンクを2件前後（例: `/training`、`/pricing`、サービスページ）。各リンクに一言の説明を付ける |
| 8 | まとめ（h2） | 1段落。前提 → 観点 → 読者が得るもの、の順に要約する。新しい情報は足さない |
| 9 | FAQ（`faq`） | 3問。比較・判断の場面で実際に聞かれる問い。1問は「MGCではできるか」に答える |

- 文字数の目安は本文2,000〜3,000字。水増しはしない。
- 業界別の記事でも同じ型を使う。観点の節は、その業界の業務に合わせて立てる（例:「チェックリスト2：検査の基準を先に決める」）。

### 1-2. 見出しの立て方
- h2 は「番号・観点：要点」の形にそろえる。読者の疑問に答える言葉で書く。
  - 良い例:「チェックリスト2：内容がツールの操作で終わらないか」「初期費用：成果をほぼ決める部分」
  - 避ける例:「AIの可能性」「今後の展望」（答えが想像できない見出し）
- h3 は原則使わない。分けたくなったら h2 を分ける。
- 見出しに数字の効果（「○％削減」）を入れない。

### 1-3. 文体・トーン
- です・ます調。落ち着いた実務の語り口で、煽らない（「劇的」「革命」「必須」などの強い言葉を避ける）。
- 読者は、その業界の経営者・管理者・担当者。ITに詳しくない前提で、専門語は初出で一言説明する。
- 1文は40〜60字程度、1段落は2〜4文。結論を段落の最初に置く。
- 断定は「判断の観点」までにとどめ、効果の保証や、出典のない数字は書かない。
- 「AIに任せる作業」と「人が持つ判断」を分けて書く。これはMGCの全コラムに共通する視点。

### 1-4. チェックリスト・表・箇条書きの使い方
- 観点の節は「確認項目の箇条書き（3〜4項目）→ 段落」の順にする。
- 確認項目は「〜か」「〜があるか」で終わる問いの形にする（読者がそのまま社内で使える）。
- 手順は番号付き（`ol`）、確認項目や要素は番号なし（`ul`）。
- 比べるもの（例: 初期・月額・実費）が3つ以上あるときは、最初に一覧（`ul`）で全体像を見せてから、1つずつ節にする。
- 引用（`quote`）は1記事に1回まで。要点を1文で言い切るときだけ使う。

### 1-5. 導入と結び
- 導入（リード）は、読者がすでに抱えている状況から入る。会社紹介から始めない。
- 結び（まとめ）は、本文の要約だけにする。売り込みの文は書かない（相談の導線はサイト側で自動で付く）。

### 1-6. CTA・内部リンクの置き方
- 本文の「MGCの場合」の節の直後に `links` ブロックを置く（`{"type":"links","items":[{"href":"/training","label":"…","desc":"…"}]}`）。href はサイト内のパスのみ（ビルドで検査される）。
- 用語集への自動リンク（初出のみ）、「このテーマに関するMGCのサービス」、関連コラム、相談CTAは、ビルドが自動で付ける。本文に重ねて書かない。
- MGCの事実として書いてよいのは、サイトに公開済みのものだけ。主なもの:
  - 研修: 1名 398,000円（税込）、標準20時間（OFF-JT）、対面／オンライン（同時双方向）、全企業同一条件。研修後の伴走オプションは個別見積もり。助成金の活用を検討する場合は申請をサポート（研修受講者は無料、受給できるかは要件による）
  - AIソリューション（AI営業・AI電話・Salesforce AI）: PoC 100〜300万円が目安、本番導入は要件に応じて個別見積もり。パイロット運用（PoC）2〜4週間・本番運用1〜3ヶ月が目安（スコープで変わる）
  - 初回相談・お見積もりまで無料。専門チームが一貫して担当
- 新しい数字・事例・社名・お客様の声は書かない。
- 日次の自動投稿は、公開前に `scripts/column/fact-check.mjs` で検査される（未公開の金額・出典のない割合・事例/実績の表現など）。手で書いた記事も `node scripts/column/fact-check.mjs <slug>` で確かめられる。

### 1-7. 既存コラムを直すときの決まり
- URL（slug）、タイトル（`title`・`seoTitle`）、書いてある事実は変えない。新しい数字・事例・社名は足さない。
- 構成と書き方だけを、この型に合わせて整える（前提の節 → 観点の節 → MGCの場合 → リンク → まとめ → FAQ）。
- 直したら `dateModified` を更新し、IndexNow に通知する。
- 事実が変わっていないことは `node scripts/column/check-rewrite.mjs <slug…>` で確認する（本文中の数字が元の記事か公開済みの事実にしかないこと、タイトル・slug が同じことを検査する）。

## 2. サムネイル

### 2-1. デザイン
- 写真調（フォトリアル）。明るい日本のオフィス・職場で、日本人のスタッフが業務をしている自然な場面。
- 色: 白・ライトウッド・コンクリート・グレー、服装は黒・チャコール・グレー・白。アクセントは青 `#2D6CDF` の小物1つだけ（画面のグラフ、タブレット、ファイル等）。暖色（ピンク・コーラル・オレンジ・赤）は出さない。
- 構図: 自然光、目線の高さ、人物は作業に集中していてカメラを見ない。余白を多めに。
- 文字・数字・ロゴ・透かしは入れない。
- 基準の画像: `/assets/service_training.webp`（研修の選び方チェックリストのサムネイル）。

### 2-2. 生成方法（誰が作っても同じ見た目にする）
1. プロンプトを作る: `node scripts/column/thumbnail-prompt.mjs <slug>`
   - 画風（`STYLE`）は固定。記事ごとに変わるのは「場所」（業種で決まる `SETTINGS`）と「場面」（タイトルのキーワードで決まる `SCENES`）だけ。
   - キーワードで場面が合わない記事は、記事 JSON に `"thumbnailScene": "英語の場面説明"` を書くとそれが優先される。
2. 画像を生成する: Higgsfield の `gpt_image_2_5`（`aspect_ratio: 16:9`、`quality: medium`、`resolution: 2k`）にそのプロンプトを渡す。
3. サイズをそろえて置く: `node scripts/column/thumbnail.mjs <slug> <生成画像のURLまたはファイル>`
4. 記事 JSON の `"image"` を `"/assets/column/<slug>.webp"` にする。

### 2-3. サイズとファイルの置き場所
| 用途 | ファイル | サイズ | 形式 |
|:--|:--|:--|:--|
| 一覧・記事のサムネイル | `public/assets/column/<slug>.webp` | 1400×788（16:9） | WebP 品質80 |
| OGP・構造化データ | `public/assets/column/<slug>.jpg` | 1200×630 | JPEG 品質82 |
| 業種の予備画像（記事に画像が無いとき） | `public/assets/column/ind_<業種>.webp` / `.jpg` | 同上 | 同上 |

- `build-columns.mjs` は、`image` が `.webp` で同名の `.jpg` があれば、OGP（og:image・twitter:image）と構造化データに `.jpg` を使う。
- 日次の自動投稿では、記事の公開と同時に `scripts/column/thumbnail-gemini.mjs` が Gemini の画像生成で個別の画像を作る（同じ `promptFor` のプロンプト、同じサイズ・形式）。失敗した日は業種の予備画像が使われ、公開は止まらない。
- 既存の記事に後から個別の画像を作るときは、GitHub Actions の「Column Thumbnail」を手動実行する（slug を指定、空なら個別画像の無い記事を最大5本）。Higgsfield（`gpt_image_2_5`）で作る上の手順も引き続き使える。
